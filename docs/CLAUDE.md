# پروژه فروشگاه اشتراک هوش مصنوعی

## مرجع
- سند کامل الزامات: docs/spec.md (قبل از هر کار بخوان)
- اگر بین این فایل و docs/spec.md تناقضی بود، docs/spec.md ملاک است.

## استک
Django + Django REST Framework، PostgreSQL 16، Celery + Redis،
Next.js برای سایت، aiogram برای ربات تلگرام، همه با Docker Compose.

## قواعد غیرقابل‌مذاکره
- فاز ۱ تک‌فروشنده است، ولی هر محصول، تنوع، آیتم انبار و قلم سفارش seller_id دارد.
- مبالغ فقط Decimal؛ هرگز float. تومان NUMERIC(15,0)، دلار NUMERIC(18,6).
- زمان‌ها به UTC ذخیره شوند.
- رزرو انبار با select_for_update(skip_locked=True) داخل transaction.atomic.
- هیچ آیتم انباری دو بار فروخته نشود، حتی با خرید هم‌زمان.
- هر عملیات مالی idempotent باشد (کلید یکتا)؛ اجرای دوباره فقط یک اثر داشته باشد.
- دفتر کیف پول و تاریخچه سفارش (order_events) فقط افزودنی‌اند.
- اطلاعات تحویل و فیلدهای حساس با AES-256-GCM رمزنگاری شوند؛ کلید فقط در متغیر محیطی.
- کلید API مشتری فقط به‌صورت هش ذخیره شود.
- منطق کسب‌وکار فقط در backend است؛ سایت، ربات و سرویس API هیچ قاعده‌ای ندارند.
- درگاه پرداخت و سرویس پیامک پشت واسط مشترک باشند تا قابل تعویض باشند.
- رمزها و کلیدها هرگز در کد نباشند؛ فقط در .env

## روش کار
- کار مرحله‌به‌مرحله طبق نقشه راه (M0 تا M9). قبل از نوشتن کد، طرح را کوتاه توضیح بده.
- برای هر قاعده مالی تستی بنویس که با برداشتن محافظ مربوط شکست بخورد.
- بعد از هر مرحله تست‌ها را اجرا کن و نتیجه را گزارش بده.
- migration نسخه‌دار؛ هیچ تغییر دستی در دیتابیس.

## نقشه راه
- M0: اسکلت پروژه، Docker، دیتابیس، Celery، نشانی /health
- M1: کاربران، ورود با کد پیامکی، کارکنان، نقش‌ها، ورود دومرحله‌ای ادمین
- M2: کاتالوگ، تنوع، قیمت دلاری با حاشیه، انبار رمزنگاری‌شده، ورود CSV
- M3: سبد، سفارش، رزرو ۱۵ دقیقه‌ای، درگاه پرداخت، verify و استعلام
- M4: تحویل خودکار و دستی، صف اپراتور، صفحه سفارش، صف پیامک
- M5: سایت Next.js و سئو
- M6: تیکت، گارانتی، بازگشت وجه
- M7: ربات تلگرام
- M8: بخش توسعه‌دهندگان (کیف پول دلاری، شارژ، API، تسویه ساعتی)
- M9: گزارش‌ها، پشتیبان‌گیری، استقرار

## دستورها
- اجرا: docker compose up -d
- تست: docker compose exec backend pytest

## کار در محیط ابری
- ممکن است Docker در دسترس نباشد. پروژه باید بدون Docker هم اجرا و تست شود:
  تنظیمات فقط از متغیرهای محیطی (DATABASE_URL، REDIS_URL) خوانده شوند.
- فایل‌های Docker را بساز و نگه دار، ولی تست‌ها را مستقیم با pytest اجرا کن.
- هرگز کلید واقعی در کد یا commit نگذار.
- در پایان هر کار: خلاصه تغییرات، نتیجه تست‌ها و کارهایی که باید محلی تست شوند را گزارش بده.
- هرگز روی main کار نکن؛ همیشه شاخه جدید با نام feature/...
